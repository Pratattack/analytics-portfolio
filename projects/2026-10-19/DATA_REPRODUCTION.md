# Data collection and vintage control

The repository publishes code, observation fingerprints, expected measured results, compact decision outputs and applications. Large raw archives and full row-level exports are collected/generated by the pipeline rather than stored as hundreds of upload parts.

October 20 availability correction: an official collection URL returned HTTP 404 in CI. Clean CI now restores only the 13 raw source members from the immutable original release `research-2026-10-19-6d3bd3a997d8`. `restore_snapshot.py` checks the pinned full archive SHA-256, manifest member hashes and the original observation fingerprints; it never overwrites a differing existing source. This reproduces the October 19 research vintage, not a fresh official download. Source URLs and original provenance remain unchanged, and intentional new-vintage research still requires independent source review.

For the same offline restoration workflow, download `release_bundle.zip` from that named GitHub release, run `python projects/2026-10-19/restore_snapshot.py /path/to/release_bundle.zip`, then run the normal verifier. Only raw source members are restored; current source code and outputs are not replaced.

After the main-branch analytical and browser jobs pass, a separate release job publishes a commit-specific ZIP of the exact official source observations, complete outputs, workbenches and 24-case browser evidence. The tag begins `research-2026-10-19-` and ends with the commit prefix. The release is never overwritten on rerun. Extract that snapshot into a clone to reproduce this version without relying on later official revisions; `SNAPSHOT_MANIFEST.json` supplies every member hash. The release job has write permission only to publish the explicitly scoped public repository snapshot; analytical and browser jobs remain read-only.

Run `python projects/2026-10-19/collect.py` once with internet access. This downloads only official BTS and FDIC URLs listed in each source manifest. It verifies the exact BTS CSV bytes and canonical FDIC observations against `data/pinned_content.json`. FDIC records are sorted by certificate and serialized with sorted keys; response metadata and compression headers are excluded from the observation fingerprint. API counts and source definitions are checked separately. The original October 19 archive hashes remain provenance records, not a claim that a server will reproduce its ZIP timestamp byte for byte.

If any observation or required dictionary changes, collection stops and names the file. It does not silently repin. `--pin` is an explicit maintainer operation only after review; CI never uses it. `data/observed_provenance.json` records actual retrieved archive hashes and check time locally. Do not confuse today's retrieval with reconstructed historical release vintages.

After successful collection, the analyses and tests run offline. `verify_all.py` collects missing sources, checks fingerprints, rebuilds full exports, compares measured results with `data/expected_results.json`, runs independent tests and compares two fresh-process rebuilds. CI performs this from a clean checkout. The analytical datasets, dictionaries and row-level outputs remain available locally after generation.

Interactive workbenches are generated as `outputs/app.html`; open them locally or run `python projects/2026-10-19/serve.py --project airline-delay-intervention-screen` (substitute `bank-deposit-cost-attribution` for banking) and visit `http://127.0.0.1:8765/app.html`. The supplied server declares UTF-8 for linked text reports as well as the application. There is no account or upload flow. All scenario assumptions remain separate from observed research results. The GitHub browser job tests three engines, two viewport sizes, both projects, reports and applications, including invalid-input recovery and empty states.
